What the eval gate guarantees

Randomized sample

Test cases are pulled at random from live Snowflake data and sized for variance across markets and tiers. The set reflects what real traffic looks like. Nobody on the team gets to hand-pick the cases.

Platform-owned rubric

The scoring dimensions, the safety red-lines, and the bars are set and owned by the platform. Teams supply only the domain ideal answers, and we audit them.

Sampled monitoring

Safety red-lines run inline on every request. Quality is re-scored on a rolling sample of live traffic, and not on every call. Drift after launch still pulls the badge, and inference cost does not double.

The bar is set per risk tier

Risk tierExample featuresQuality barWhat a miss costs
LowListing descriptions (#6)80a clumsy sentence, easy to edit before it ships

One bar, calibrated on real customer data, set higher where a mistake costs more. For legally sensitive features (financials, screening, anything touching fair housing) the risk tier is set by a Legal review. The team does not assign its own. Screening rejection letters (#4) sit above any bar we would set. The exposure there is legal, so a higher threshold does not fix it. The answer is no.
